# Synthetic Parquet analytical case pack

`data-mcp-fixture` creates six development cases backed by eight real Parquet
order lines. Raw SQL and promoted named metrics use the same file. Fixed answers
are written separately from the MCP data root and never loaded by the server.
The pack needs no model account, database credentials or existing data source.

## Create and verify

From the data-mcp checkout after `uv sync --frozen --dev`:

```sh
mkdir -m 700 "$HOME/ana-development-cases"
uv run --frozen data-mcp-fixture create --output-root "$HOME/ana-development-cases"
```

The command prints an absolute `pack` path and `manifest_sha256`. Save those two
values. It creates a fresh UUID directory for each invocation; it never overwrites
an earlier pack. The output parent must already exist, be owned by you, have no
permissions for other users, and use an absolute path without symlink components.
For example, use `/private/tmp` instead of the macOS `/tmp` symlink.

```sh
uv run --frozen data-mcp-fixture verify \
  --pack /absolute/path/from/create \
  --manifest-sha256 DIGEST_FROM_CREATE
```

Verification checks the pinned manifest, exact file set, private permissions,
file sizes, file hashes and this version's fixed configs/definitions/labels. It
then starts two actual stdio MCP sessions and compares twelve complete, typed
integer answers with the fixed oracle. It checks the file hashes again afterward.
Failure exits 2 with a fixed diagnostic; successful stdout contains aggregate
counts and explicit evidence limits. The installed CLI also supports
`python -m data_mcp.fixture` with the same arguments.

## Cases and arithmetic

| Case | Expected total | Mistakes exercised |
|---|---:|---|
| January gross | 4800 cents | Cancelled lines; month boundaries; signed returns |
| January net | 4600 cents | Null discounts; signed return discounts |
| January orders | 4 orders | Repeated order IDs across different lines |
| January units | 6 units | Negative return quantities |
| January missing discounts | 2 lines | Null versus explicit zero |
| March net | 0 cents | Empty selection versus SQL NULL |

The five included January lines have gross values 2000, 500, 2100, -1000 and
1200; net values 1900, 500, 1900, -900 and 1200. They belong to orders A, A, B,
R and D. A cancelled January line contributes neither amounts nor order counts.
December 31 and February 1 lines test the half-open January interval. Dates are
calendar dates; this pack does not test timezone transitions or DST. All six cases
belong to one development family; none is a holdout. These synthetic cents do not
encode an independently approved accounting policy.

## Files and Mos Eisley

- `data/lines.parquet`: the entire configured Parquet root.
- `ontology/manifest.toml`: six fixed definitions and shared conventions.
- `raw.toml` and `promoted.toml`: analysis-only data-mcp launch configurations.
- `golden/cases.json`: candidate questions, SQL, units and expected values for the
  test driver; outside the data root and the ontology.
- `manifest.json`: hashes of the generated bytes, including the actual Parquet
  file and the semantic revision. Parquet byte hashes may vary by writer version.

For Mos Eisley, use its ordinary MCP config with an absolute Python executable
from an installation containing this data-mcp version:

```json
{
  "command": "/absolute/data-mcp/.venv/bin/python",
  "cwd": "/absolute/private/pack",
  "args": ["-m", "data_mcp.cli", "--config", "/absolute/private/pack/raw.toml"],
  "tools": {"list_sources": "read", "query_parquet": "read"},
  "max_result_bytes": 12000
}
```

For the promoted arm, select `promoted.toml` and grant `get_semantic_context` and
`run_metric`. Set the corresponding Mos `AnalysisConfig.context_mode` to `raw`
or `promoted`, and set its `max_result_bytes` to 12000 in both arms. This includes
room for the semantic catalog and the SDK's textual/structured result envelope.
Use the same question, including shared conventions, and the same other budgets
for both arms. The fixture tool does not start a provider conversation.

The Mos Eisley branch `feat/analysis-parquet-cases` adds an optional cross-repository
regression that scripts all twelve conversations through its checked scalar-answer
controller, then verifies the pack again:

```sh
# Run from the Mos Eisley checkout with the case-pack integration test.
DATA_MCP_TEST_PYTHON=/absolute/data-mcp/.venv/bin/python \
  uv run --frozen python -m unittest \
  tests.test_mcp_data_integration.DataMCPIntegrationTests.test_synthetic_parquet_case_pack
```

## Evidence limits and next work

Private file permissions and separate tool roots prevent accidental label exposure
through these MCP tools. They do not isolate a process with arbitrary host-file
access, and the scripted test driver deliberately knows both queries and labels.
Before/after hashes detect lasting file changes; they do not authenticate a source,
prove no temporary changes occurred during execution, or prevent the owner from
rewriting files. This is no immutable snapshot or independent review claim.

There are no provider calls, measured model-quality results, automatic expiry or
automatic cleanup. The owner manages retention of generated packs. A failed create
may leave a partial UUID directory; verification rejects incomplete packs.
The verifier accepts this fixed packaged format, not arbitrary imported configs.

Next: select the intended real-data domain, review definitions with its owner,
freeze a suitable source fixture, and prepare family-separated assessment cases
for the existing Mos evaluation/schedule flow. This pack is a regression baseline;
there is no automatic conversion to a reviewed evaluation suite or live executor.
See [verification](ANALYTICAL_CASE_PACK_VERIFICATION.md).
